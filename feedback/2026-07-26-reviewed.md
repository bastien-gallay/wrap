## The intake problem, and why it is not fixed here

26 runs produced one feedback note, on day one. The cause is structural: a wrap
running in another repo has no access to this repo's `FEEDBACK.md`, so the
iteration loop in `CLAUDE.md` is only executable during a self-wrap — the case
`CLAUDE.md` itself calls a hazard. Everything in the 07-26 batch had to be
recovered from session transcripts.

The obvious fix is for `SKILL.md` to name a global intake —
`~/.claude/skills/wrap/FEEDBACK.md`, which the symlink lands in this repo, or a
dedicated memory. It was **deliberately not folded** in this pass, for one
reason: it only works for installs that are symlinks to a writable checkout. A
`--copy` install or a plugin install would have the skill writing into its own
package directory, which is either read-only or gets clobbered on update. The
mechanism needs to be decided before it is written into a protocol that ships.

Recorded here so the next pass does not rediscover the problem from scratch, and
does not fold the naive version of the fix.

## Considered, deliberately not acted on

- **The cadence framing.** `SKILL.md` says wrap "may fire three times in a week
  or once a month". Observed usage is five times in one day, sometimes mid-session
  ("go pour volet 2, mais avant, effectue un `/wrap`"). The wording is not wrong,
  but it under-describes reality. Left alone until it is clear whether the
  protocol should absorb the checkpoint use or whether that use is drifting
  towards `/do-eod`. Partially mitigated: Orientation now derives the blast
  radius from the previous wrap when there is one, which is where repeated runs
  wasted the most.
- **`--dry-run` and `--only`.** Zero uses in 26 runs. Not enough to remove them
  — the phase slugs are load-bearing for `--only` — but enough to stop
  foregrounding them. Left in place, unpromoted.

## Batch — 2026-07-26, 26 runs reviewed, six repos, five days

Read back from the session transcripts rather than from notes, because no
notes existed — see *the intake never fired* below. 26 slash expansions across
24 sessions and six repos between 2026-07-21 and 2026-07-25: a client docs hub
17, a client monorepo 5, one each in faceto, termherd, glance, skills. Up to
five runs in one day; four sessions ran it twice. `--dry-run` and `--only` were
never used once.

### What worked

- **Seiso carried the value in every run.** The "unchanged files that talk
  about the same subject" pattern found something each time. Two worth
  naming: termherd's `run_in_session` tool description was actively pointing
  agents at the poll-race the merged PR had just removed — the text an LLM
  reads *at the moment it picks the tool*; and faceto's `docs/ci.md`, declared
  canonical for CI jobs, was missing three third-party actions and an entire
  second workflow.
- **The empty-phase rule held everywhere.** Two runs closed with "no commits —
  everything this session touched is outside git". Several reported "0 lessons
  promoted" with the reasoning. No busy wrap in 26 runs.
- **Supersede-don't-rewrite is applied unprompted**, including the hard part:
  `~~struck~~` plus **Superseded**, plus a line disambiguating the
  near-contradiction it leaves behind.
- **Stale summary lines became the recurring quarry** — "body reconciled,
  summary line left behind", caught at least three times. Once on a line that
  had survived an entire consolidation pass.

### Friction — the pass stops one step short of shipped

Eight or more occurrences. Every run ends on "N commits proposed", and the
user then has to say `go`, then `push`, then `open the PR`. Verbatim: "go, et
pousse" · "commit + push + MR" · "commit (hors sandbox autorisé) puis push" ·
"push et ouvre la PR". The autonomy contract has one row for git; execution
serialises it into three turns. The out-of-sandbox / signing authorisation is
asked for separately again, mid-sequence.

### Friction — the `.wrap.md` never writes itself

Four occurrences, including both of the most recent runs: "il devrait y avoir
un `.wrap.md` maintenant" · "est-ce qu'on peut ajouter un `.wrap.md`?" · "écris
le `.wrap.md`" · "oui, ajoute `.wrap.md`". §3 said to offer it *at the very
end*, which puts it behind the commit proposal, where it gets swallowed.

Worth recording separately: both runs that did write one put lessons in it
about *how to wrap that repo* — "a worktree's removal is verified against the
PR state, not `git log main..branch`, because PRs are squash-merged", and
"`.impeccable` caches get ignored, not deleted, since they regenerate". The
`## Notes` section of `.wrap.md` is a Seiketsu destination, and the routing
table did not list it.

### Friction — parallel sessions are not in the protocol

Five-plus occurrences, all in the client docs hub: "`AGENTS.md` est modifié
par une autre session : je n'y touche pas" · "trois commits d'autres sessions ont
atterri sur `main` entre ma vérification et mon merge" · "le fichier bouge
sous moi" · "les commits de l'autre session sont faits. Go".

The improvised handling was right — don't touch a file another in-flight
session owns, defer the promotion, leave it uncommitted and say so explicitly,
`pull --rebase` before pushing. None of it was written down anywhere.

### Friction — the blast radius stops at the repo, reality does not

Three runs. Seiso found *tracker tickets* carrying the premise the session had
just killed: one sitting in `READY FOR DEV` on a dead justification, one holding
the identified mechanism with nobody assigned, one ready to close.
Separately, a README drift found during faceto's wrap was routed as a comment
on issue #102 rather than fixed, because it was outside the milestone.

The caution that emerged is worth keeping verbatim: "aucune étiquette touchée
— sur ce projet, modifier les labels peut déplacer le statut d'un ticket via
une automatisation. Un commentaire est le geste sûr."

### Friction — the user keeps having to ask for the recommendation

Five occurrences: "contrôle ce qui doit l'être et conseille moi" · "que me
conseilles-tu?" · "tu conseilles quoi?" · "ton conseil?". The closing table
summarises; it does not recommend. The one run that volunteered a "Mon
conseil, par ordre" is the one that did not draw the question.

### Friction — `§n` references were explicitly rejected

> go. Et arrête de juste me sortir des §6 comme ça, stp. ces références §n ne
> veulent rien dire dans ma mémoire. ou alors avec un gros effort de recherche

These were sections of *repo documents*, not of `SKILL.md`. wrap emitted them
constantly all the same — "la ligne du §6", "§0 révisé", "§5 après les
hypothèses retirées".

### Friction — no copy-pasteable handoff

Four runs were followed immediately by `/copy`, and one invocation asked for
it outright: `/wrap et dis-moi ce que je dois te dire pour reprendre la suite
dans une nouvelle session`. Three runs were followed by `/schedule` — "reprendre
ce travail lundi après-midi", "ajoute un rappel pour markdown vendredi à 16h".

Also: free-text arguments are in use (`uniquement pour le skill wrap`, `pour
reprise demain matin`) while `argument-hint` documented only the two flags.

### The commit-split friction got its second occurrence

The 2026-07-21 batch left this open, saying not to fold it until a second run
hit the same wall. It did, in termherd: `AGENTS.md` carried both a factual
reconciliation and a promoted lesson. Resolved by "mettant temporairement le
bloc de la leçon de côté pour ne stager que la réconciliation, puis en le
restaurant" — the same backup-revert-replay in miniature, and it worked.

The first run's near-miss stays relevant: one `perl` substitution failed
silently mid-replay and was caught only because `git diff --stat` showed one
changed line where three were expected.

### The cost, measured

wrap reached 8% of skill usage, against 9% for `/code-review`, while plainly
doing less work. Measured across the 26 runs — **upper bound**, since
everything after a `/wrap` is attributed to it, including the push, the PR,
and follow-up questions:

```text
assistant turns          1 734 total        66.7 per run
cache-read tokens        424.5 M            16.3 M per run
output tokens              1.52 M            58 k per run
tool calls                   837              32 per run
  Bash 563 (191 of them starting with `cd`) · Edit 188 · Read 63 · Write 16
```

The shape: 32 tool calls against 67 turns means **half the turns are prose
between two tool calls**. Average cache-read per main-loop turn is 245 k,
because wrap runs at the end of a long session and every turn — including a
`grep` — re-reads a context that is already maximal. 191 Bash calls out of 563
begin with `cd`, i.e. one command per call, never batched.

Findings are also restated up to five times: phase narration, then a
"Seiso en détail" table, then the closing table, then the commit body, then
the PR body.

### The intake never fired

26 runs, one entry in `FEEDBACK.md`, dated the first day. The reason is
structural, not negligence: a wrap running in a client repo or in termherd has no
access to `FEEDBACK.md`, which lives in this repo. The iteration loop in
`CLAUDE.md` is only executable during a self-wrap — precisely the case
`CLAUDE.md` calls a hazard. Everything above had to be recovered by transcript
archaeology.

## Batch — 2026-07-21, first run, on this repo, against itself

Conditions were the most favourable possible: a one-hour-old repo, no
residue, no accumulated contradiction. Treat the verdicts below as
provisional — most phases were never stressed.

### What worked

- **Seiso earned the whole pass.** It found two superseded figures across
  four files, including the number used to *illustrate* index drift in the
  Seiton section. Grepping for the claim rather than fixing the files already
  open is what caught the third occurrence.
- **The empty-phase rule held.** Seiri and Seiton reported nothing without
  manufacturing activity. The "busy wrap" warning did its job.
- **Supersede-don't-rewrite produced a real artifact.** The first commit's
  "~590 commits" is wrong and stayed wrong; `CLAUDE.md` carries the correction
  plus a "looks like a contradiction, is not" line pointing at it.

### Friction — one commit is one idea, but ideas share files

One idea per commit is mandated. The run produced four ideas across three
files, and **three of the four ideas touched `CLAUDE.md`**. Interactive
`git add -p` is unavailable in this harness.

Worked around it by: backing the final files up outside the repo, reverting
to HEAD, and replaying the edits in commit order. It worked — a final `diff`
confirmed byte-identity with the backup — but it is fragile, and one `perl`
substitution silently failed mid-replay because the pattern omitted the
leading indent. Caught only because `git diff --stat` showed one changed line
where three were expected.

`SKILL.md` said nothing about *how* to split when ideas share a file. It
should: either name the backup-revert-replay recipe, or say plainly that
bundling is acceptable when the alternative is patch surgery, and let the
commit body enumerate the ideas.

Unresolved at capture time: which of the two. **Resolved 2026-07-26** — the
second occurrence arrived (termherd), the lighter form of the recipe worked, and
it is now written down. Bundling was not adopted.

### Friction — the symlink makes a self-wrap non-reproducible

The install is a symlink, so editing `SKILL.md` during the pass changed the
protocol while it ran. Seiso gained a new directive *while Seiso was
executing*. Harmless there, but a self-wrap is not a clean test of anything.

Already mitigated in `CLAUDE.md`'s iteration loop (capture during, edit
after). Left here because the mitigation is documented, not enforced, and the
next self-wrap will be tempted the same way. Still true on 2026-07-26: this
fold was done outside a wrap run, deliberately.

### Not friction, worth recording

The three-phases-untested state is in `CLAUDE.md § State`, not here — it is
repo state, not protocol feedback. **Closed 2026-07-26**: 26 runs across six
repos have now exercised all five phases on external milestones.
