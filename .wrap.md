# wrap — configuration for its own repo

The skill wrapping itself. Kept at root rather than under `.personal/`
because this is a single-author public repo and the config is part of what
ships as an example.

## Canonical locations

- lessons: CLAUDE.md
- decisions: CLAUDE.md
- journal: CHANGELOG.md
- tracker: github issues

No `index` key: this repo has no status table that drifts. The nearest thing
is `README.md`'s phase table, and `CLAUDE.md` already records that only the
phase *slugs* need to track `SKILL.md` — the English glosses may diverge.

No `skills` key either. This repo *is* the skill; an operational lesson goes
into `SKILL.md` itself, not into a sibling. Durable lessons about working on
the repo go to `CLAUDE.md`, which doubles as the decisions file — its
`## Design decisions worth not re-litigating` section is the retired-hypotheses
table under another name. `CHANGELOG.md` is the journal: dated, append-only,
one section per released version.

## Verification commands

- blocking: npx --yes markdownlint-cli2 '**/*.md'

`markdownlint-cli2` auto-detects `.markdownlint.jsonc`. `MD013` and `MD033`
are disabled there on purpose — do not re-enable them to make a wrap pass.

There is no test suite and there will not be one. The prose is the product;
`markdownlint` plus a human reading it is the whole gate.

## Disposable zones

- dist/
- .DS_Store
- node_modules/
- .impeccable/

`dist/` holds `.skill` archives if `just package` is ever added here — build
output, never edited by hand. `.impeccable/` holds a regenerating hook cache:
ignore it, never delete it. It was ignored only through this clone's
`.git/info/exclude` until 2026-07-26, which meant a fresh clone saw it dirty.

## Commit conventions

- format: <the conclusion, lowercase, no type prefix>
- one commit is one idea

**This deliberately diverges from the template** in
`skills/wrap/templates/wrap-config.md`, which suggests
`<type>(<scope>): <conclusion>`. All sixteen non-merge commits in this repo
carry no conventional prefix at all — the subject is the bare claim. Verified
against `git log`, not assumed.

One exception, and it is not a drift: the single merge commit reads `Merge pull
request #1 from …`, GitHub's default. Merge subjects are not conclusions and are
not expected to be.

Subjects read as conclusions: "only the phase slugs are load-bearing, not
their English glosses", "a figure copied from a subagent is a superseded
claim in waiting". Bodies run 3–8 lines and say what changed and why.

## Notes

- **Version bumps touch two files** — `.claude-plugin/plugin.json` *and*
  `.claude-plugin/marketplace.json`. Bumping one is a silent freeze. A wrap
  that changes `SKILL.md` behaviour should check both, plus a matching
  `CHANGELOG.md` section.
- **`SKILL.md` is a shipped binary.** Every edit is release-eligible. Treat a
  wording change to a hard rule as a behaviour change, not a typo fix.
- **Prose wraps at ~78 columns**; the phase tables and the sample output run
  wider on purpose.
- **The installed copy is a symlink** (`~/.claude/skills/wrap` →
  `skills/wrap`), so edits to `SKILL.md` are live immediately. A wrap run in
  this repo is editing the skill that is running it.
- **The symlink exposes the checked-out branch, not just uncommitted edits.**
  It points at the worktree, so `git switch` silently changes which version of
  the protocol is installed — a `switch` to a branch predating a release
  downgrades the live skill with no reinstall and no warning. Stay on `main`
  unless you mean to run an older protocol. Version bumps in the manifests are
  irrelevant to this install; they only matter to a marketplace install.
- **Do not carve a wholesale rewrite into per-idea commits afterwards.** Tried
  on 2026-07-26: staging whole hunks by content anchor worked, but displaced
  continuation lines — a bullet's first line in one commit, its remainder in
  another position — and needed a named reconciliation commit to repair. The
  recipe in `SKILL.md` covers a file carrying two ideas, not a file rewritten
  from scratch. Edit the protocol one idea at a time instead.
- **Section order decides what can be committed apart.** The configuration
  tail and the whole of Orientation are contiguous, so three distinct ideas
  had to travel in one commit. Worth knowing before planning a split.
